# Final Project Prototype — Permanent Deployment

## Project
**PRIVACY-PRESERVING FEDERATED LEARNING FRAMEWORK FOR MULTI-HOSPITAL MEDICAL DATA ANALYSIS**

CKD is the case study. The project uses four simulated hospital clients built from public CKD datasets, hospital-wise missing-feature simulation (5%, 15%, 25%, 40%), proposed adaptive privacy perturbation settings (0.05, 0.10, 0.20, 0.30), local training, protected updates, FedAvg, performance metrics, and a confidence-based MIA prototype.

## Files
- `train_colab.py` — full training/experiment code. Run this in Google Colab.
- `app.py` — permanent Gradio dashboard for Hugging Face Spaces.
- `requirements.txt` — deployment dependencies.
- `CKD_Federated_Project_Output/` — generated by `train_colab.py`; copy it into the Space after training.

## Colab
Run `train_colab.py` in Google Colab. It downloads UCI 336, Kaggle Chronic Kidney Failure Dataset Reboot, and UCI 857, trains Normal FL / Fixed-DP FL / Proposed Adaptive-DP FL, generates CSV results, graphs, model/config files, and the complete project PDF.

## Permanent hosting
1. Create a **Gradio Space** on Hugging Face.
2. Upload `app.py`, `requirements.txt`, and the entire `CKD_Federated_Project_Output` folder.
3. The Space runs with `demo.launch()` — no `share=True` temporary tunnel.
4. Every commit is saved in the Space repository, so the project URL is persistent. Free Spaces can sleep when idle; waking them does not change the URL.

Suggested repository layout:
```
app.py
requirements.txt
README.md
CKD_Federated_Project_Output/
  model/
  results/
  graphs/
  reports/
```

## Academic notes
- Hospitals are simulated clients, not real hospitals.
- The missingness-to-noise mapping is a proposed experimental mechanism, not a clinically established rule.
- The current update perturbation is a DP-style research mechanism; do not claim formal epsilon/delta guarantees unless a formal DP accountant/calibration is added.
- MIA is a confidence-based prototype attack.
